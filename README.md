# Student Placement & Salary Predictor

End-to-end machine learning system that predicts two outcomes for students
from academic, behavioral, and demographic features:

1. **Placement Status** (classification) — will the student be placed or not
2. **Estimated Salary** (regression) — expected salary in LPA (Lakhs Per Annum)

Built in two deployment styles to compare architectures: a **monolithic
Streamlit app** (model loaded in-process) and a **decoupled FastAPI backend +
Streamlit client** (frontend talks to the API over HTTP).

## Pipeline architecture

```
data/A.csv, A_targets.csv
        │
        ▼
  data_ingestion.py        merge raw features + targets → ingested/A_merged.csv
        │
        ▼
  feature_engineering.py   derived features (academic_score, experience_index,
        │                  skill_avg) + numeric/categorical column split
        ▼
  train_test_split         80/20, stratified
        │
        ▼
  train.py                 sklearn Pipeline (SimpleImputer + Scaler/Encoder +
        │                  model) for both tasks, tracked in MLflow
        ▼
  evaluation.py             metrics computed + logged to MLflow
        │
        ▼
  check_model_threshold()  approve/reject gate — model must clear minimum
        │                  accuracy/F1/ROC-AUC (classification) or R²/MAE
        │                  (regression) before it's allowed to deploy
        ▼
  models/*.pkl              approved models saved
```

Run the whole thing end-to-end with `pipeline.py`, which orchestrates every
step above and prints a pass/fail summary against the thresholds.

## Deployment (two ways)

**1. Monolithic — `app.py`**
Single Streamlit process, model loaded directly in-app. Simplest to run and
deploy (e.g. Streamlit Cloud).

**2. Decoupled — `api.py` + `frontend.py`**
- `api.py`: FastAPI backend serving `/predict/classification`,
  `/predict/regression`, `/predict/combined`, and a `/health` check —
  request/response validated with Pydantic models, errors handled explicitly.
- `frontend.py`: separate Streamlit client that calls the API over HTTP
  instead of loading the model itself — the pattern you'd use if the model
  needs to serve multiple clients (web, mobile, other services) rather than
  being baked into one app.

## Quality gating

Models aren't deployed automatically — they have to clear a minimum bar,
checked in `evaluation.py`:

| Task | Metric | Threshold |
|---|---|---|
| Classification | Accuracy | ≥ 0.75 |
| Classification | F1 (weighted) | ≥ 0.75 |
| Classification | ROC-AUC | ≥ 0.80 |
| Regression | R² | ≥ 0.50 |
| Regression | MAE | ≤ 5.00 LPA |

## Features used

**Numeric:** CGPA, 10th/12th grade percentage, backlogs, study hours/day,
attendance %, projects completed, internships completed, coding/communication/
aptitude skill ratings, hackathons participated, certifications count, sleep
hours, stress level — plus engineered features `academic_score`,
`experience_index`, `skill_avg`.

**Categorical:** gender, branch, part-time job, family income level, city
tier, internet access, extracurricular involvement.

## Run locally

```bash
pip install -r requirements.txt

# Run the full training pipeline (ingestion → features → train → evaluate → gate)
python pipeline.py

# Option A: monolithic Streamlit app
streamlit run app.py

# Option B: decoupled FastAPI + Streamlit client (run in two terminals)
uvicorn api:app --reload --port 8000
streamlit run frontend.py
```

API docs (Swagger UI) are auto-generated by FastAPI at `http://localhost:8000/docs`
once `api.py` is running.
